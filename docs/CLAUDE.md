## Engine and build

- Unreal Engine 5.9 Preview, C++ project from the Top Down template. Windows 10, Visual Studio 2022.
- Names: the project is KillingPart (KillingPart.uproject, targets KillingPart and KillingPartEditor, game exe KillingPart.exe). The C++ module is still called CardIsland on purpose (renaming it breaks Blueprint references), and so is the project folder (Diversion, Claude Code and Claude's file access are tied to it). Don't rename either.
- Build: close Unreal, run BuildEditor.bat in the project root. It writes Saved\BuildLog.txt and opens the editor when the build succeeds. It refuses to run while Unreal is open.
- With Unreal open (needed for the Unreal MCP), Live Coding (Ctrl+Alt+F11) compiles changes inside .cpp function bodies only. New files, header changes, new UPROPERTYs or UFUNCTIONs need Unreal closed and BuildEditor.bat.
- Our game code lives in Source/CardIsland/KillingPart, classes prefixed KP. The template's classes (CardIslandCharacter, CardIslandPlayerController, CardIslandGameMode) and the Variant_* folders are Epic's template: leave them alone.
- Maps: /Game/KillingPart/Maps/Lvl_Mat is the arena (from T2 on). The packaged build must list only our maps.
- Data: Content/Data/KillingPart.json. Edit it without recompiling, then restart Play. When Unreal offers to import it as a DataTable, click Cancel. DefaultGame.ini must stage Content/Data with +DirectoriesToAlwaysStageAsUFS=(Path="Data") (T1 adds it) or the JSON won't ship.
- Colouring basic shapes: the /Engine/BasicShapes meshes use DefaultMaterial, which has no Color parameter. Make the dynamic instance from BasicShapeMaterial, CreateDynamicMaterialInstance(0, BasicShapeMaterial), with the material loaded at runtime by LoadObject (a constructor FObjectFinder for it fails at module init). DefaultGame.ini always-cooks /Engine/BasicShapes so it ships.
- Useful template assets: /Game/Characters/Mannequins (SKM_Quinn_Simple, SKM_Manny_Simple, animations in Anims), /Game/LevelPrototyping (grid materials, good for the cutting mat), /Game/Cursor/FX_Cursor (a Niagara system), /Game/Variant_TwinStick/FX (may have bursts worth recolouring).

## Code conventions (these broke or nearly broke the build)

- ASCII only in source files.
- FString::Printf and UE_LOG: the format must be a TEXT("...") literal, never a ternary; %s takes *SomeFString or a const TCHAR*.
- Never name a local, parameter or UPROPERTY after an engine member (Role, Owner, Tags, Instigator, Controller, ...): shadowing is a compile error.
- Unity builds: helper namespaces and statics need names unique across the module.
- Times are double (GetTimeSeconds returns double).
- Prefer code to Blueprints: UI is Slate in code, and input can be polled in a Tick (WasInputKeyJustPressed, IsInputKeyDown).
- Slow motion is global time dilation, so anything that must run at real speed (the dash, the beat, UI timers) uses undilated time.
- Materials used on instanced static meshes need bUsedWithInstancedStaticMeshes, or they render as the default material at runtime. Unlit colours go through EyeAdaptationInverse (M_KPUnlit) so the night exposure doesn't darken them.
- M_KPCap is built by Tools/build_cap_material.py (run it in the editor's Python) (bands from r = |local position / Radii|, which is 1 on the body surface). Changing it makes the next editor start compile shaders for minutes; MCP calls are refused until that finishes.
- Niagara sprites: use M_KPSprite (opaque masked, exposure-corrected). The default sprite material is translucent and adds light, so dark colours like blood come out pale over the mat.
- Editing Niagara over the MCP works (NiagaraToolset_System: SetStackInputData, AddUserVariables, SetRendererData), but GetEmitterInputValues returns a huge payload: summarise it in the Python script before returning.
- In editor Python, unreal.Color(...) positional args are B, G, R, A. Always pass r=, g=, b=, a=.

## Unreal MCP

- .mcp.json points to http://127.0.0.1:8000/mcp. Unreal must be open with its MCP server running.
- The server doesn't start by itself (bAutoStartServer is off). After T1, BuildEditor.bat launches the editor with -ModelContextProtocolStartServer. Otherwise run `ModelContextProtocol.StartServer` in the editor console, or tick auto-start in Editor Preferences, Model Context Protocol.
- If Claude Code started before Unreal, its unreal-mcp tools stay unloaded until `/mcp` reconnects. The server is plain JSON-RPC over HTTP, so it can also be called directly (initialize, then tools/call with the Mcp-Session-Id header). The execute_python tool in editor_toolset.toolsets.python_scripting.PythonScriptingTools runs editor Python and is the fastest way to build or change level content.
- Testing in Play over MCP: LevelEditorSubsystem.editor_request_begin_play(), console commands via unreal.SystemLibrary.execute_console_command(game_world, "kp.Wave 4"), a drawn cut via SlateInspectorToolset MouseDown/MouseMoveTo/MouseUp on the PIE viewport widget (find its ref with Snapshot, "viewport"), and screenshots via SceneCaptureToolset.CaptureGameViewport (image.data is base64 PNG). Offscreen Capture ignores the fixed exposure, so judge brightness from CaptureGameViewport.
- Live Coding can be triggered with the console command LiveCoding.Compile (function bodies only).
- Hands-free testing: kp.God 1 + kp.AutoCut 1 makes her cut by herself (the log prints "Snip: sliced N in X ms"). The Slate viewport widget shows up in Snapshot only after Observe on the main window (ref w_1); its line reads "viewport [focused] [pos=...] [ref=vp_1]".
- Claude Code connects over HTTP directly. Claude Desktop needs the mcp-remote bridge, which fails with "Expected protocolVersion string and clientCapabilities object in params._meta" while Unreal's Maximum Protocol Version (Editor Preferences, Model Context Protocol) is 2026-07-28. Lowering that setting is the likely fix for Claude Desktop.
